How it works

  • Cache read price = if(Model = 1, 0.2, if(Model = 2, 0.1, if(Model = 3, if(Context re-read per turn (cached) + New context per turn (cache write) > 100, 0.05, 0.01), 0.25)))
  • Cache write price (5-minute) = if(Model = 1, 5, if(Model = 2, 2.5, if(Model = 3, if(Context re-read per turn (cached) + New context per turn (cache write) > 100, 0.625, 0.125), 12.5)))
  • Output price = if(Model = 1, 20, if(Model = 2, 10, if(Model = 3, if(Context re-read per turn (cached) + New context per turn (cache write) > 100, 2.5, 0.5), 50)))
  • Cost per turn = (Context re-read per turn (cached) × Cache read price + New context per turn (cache write) × Cache write price (5-minute) + Output per turn × Output price) ÷ 1,000
  • Cost per day = Cost per turn × Model turns per day
  • Cost per month = Cost per day × Working days per month
  • Share of cost spent re-reading context = 100 × Context re-read per turn (cached) × Cache read price ÷ max(Context re-read per turn (cached) × Cache read price + New context per turn (cache write) × Cache write price (5-minute) + Output per turn × Output price, 0.000001)

About this tool

Claude Code sends the whole conversation back to the model on every turn: your instructions, the files it has read and every earlier tool result. With prompt caching, the part that was already sent is billed at the cache-read rate, new context at the cache-write rate, and the model's reply at the output rate. This calculator multiplies those three amounts by the published per-million-token prices for the model you pick.

Cache reads are cheap per token, but there are a lot of them. On Opus 5.5 a cache read costs $0.20 per million tokens, 5% of the $4 input price, while output costs $20 per million. A session carrying 80,000 tokens of context re-reads all of it on every turn, so over hundreds of turns the re-read can rival what you pay for output. In the sample report in burn's README (one heavy user's machine), 45% of the API-equivalent cost was context re-read from the cache.

The defaults (200 turns a day, 80k tokens of context, 4k new tokens and 1k output tokens per turn) are a starting point, not a measurement. A turn is one model call, and one request in Claude Code often takes several turns, because each tool call is a turn. Haiku 5.5 is priced higher for prompts over 100,000 tokens, and the calculator switches to that tier when the per-turn context plus new tokens passes the line; it uses your per-turn figures as an average, so real sessions with some longer turns can cost more. Cache writes are priced at the 5-minute rate; the 1-hour cache costs more.

On a Pro or Max subscription you are not billed per token, so treat the result as a rough gauge of how heavy your usage is, not a bill. To replace the guesses with your own numbers, run burn on your machine: it reads the local session logs, makes no network calls and prints your cost by model and the share spent re-reading context.

Questions

Why is cached context billed at all?

The cache saves the model from reprocessing the same tokens, so cache hits are billed at a small fraction of the input price rather than free. That fraction is 5% on Opus 5.5 and Sonnet 5.5, 10% on Haiku 5.5 ($0.01 of its $0.10 input price) and 2.5% on Fable 5.1.

Do Pro and Max plans pay these prices?

No. Subscriptions include Claude Code usage up to plan limits instead of per-token billing. These prices apply when Claude Code runs on an API key billed through the Claude Platform.

Is a turn the same as a message I type?

No. One message can trigger many model turns, because Claude Code makes a new model call after each tool use, such as reading a file or running a command.

What are tokens, context and a turn?

A token is a small piece of text, roughly three quarters of a word. Context is everything Claude Code sends back to the model on each call: your instructions, files it has read and earlier results. A turn is one model call. One message you type can start several turns, one per tool use.
